01 · History

Where Theoryscope came from.

When was Theoryscope first created?

Built at Copenhagen Business School, Denmark, during an Otto Mønsted Visiting Professorship in 2026. The support of the Otto Mønsted Fond (grant 25-12-1849) is gratefully acknowledged.

The first commit, a Phase 0 scaffold, is dated 17 April 2026. David M. Berry of the University of Sussex designed the tool and built it with Claude Code. A reading list on the renormalisation group and the genealogy of deep learning, compiled by John Hessler, prompted the project.

How was it developed?

In numbered phases, each recorded in the commit history and the roadmap in the README.

  • 17 April 2026, Phases 0 to 3A. Scaffold and the built-in Phase 0 corpus; the Eigendirections operation; Zotero ingestion, provenance export and the disk cache; the first Flow operations (aggregative k-means coarse-graining); and the Critique tab, opened with the Embedding Dependence Probe, Perturbation Test and Forgetting Curve.
  • 21 April, Phase 4A. Inspect tab completed with the Concept Locator, Author Constellation and Debated vs Computed.
  • 22 April, Phase 4B. Flow tab completed with the Operator Spectrum and Temporal RG Flow.
  • 23 April, Phases 4C, 4D and 5A. Critique tab completed with the Symmetry Breaking Map, Phase Diagram and Translated Corpus Probe, then the Corpus-vs-Model Probe. Seventeen operations live.
  • 13 June, Phase 5B. Branding brought into line with the other Vector Lab instruments.
  • 9 August, v0.8.1. Relicensed from MIT to GPL-3.0-or-later.
  • 27 October, v0.8.2. This documentation site published, and the release archived on Zenodo with a DOI.
  • November 2026. Model recommendations added to the app and the docs.

What is still planned?

A Critical Annotations Layer, for Markdown notes attached to any eigendirection, fixed point or basin and exported with the result; the Atlas, a set of curated pre-run analyses on named corpora; and semantic, lexical and citation-graph coarse-graining operators alongside the current aggregative one.

Is Theoryscope part of a larger project?

Yes. It is one of the instruments in the Vector Lab, alongside Vectorscope, Manifoldscope, Manifold Atlas and LLMbench. The others take a model as their object; Theoryscope takes a corpus.

02 · Code and citation

Source, releases and licence.

Where is the source code?

On GitHub at github.com/vector-lab-tools/theoryscope.

  • Releases, with notes for each version.
  • Commit history, from the Phase 0 scaffold onwards.
  • Issues, for reporting problems.
  • The source of this site, in the docs/ folder.

How do I cite Theoryscope?

Each release is archived on Zenodo. The concept DOI 10.5281/zenodo.23715027 always resolves to the latest version. Suggested citation:

Berry, D. M. (2026). Theoryscope: a renormalisation-group workbench for corpora of theoretical texts [Software]. Zenodo. https://doi.org/10.5281/zenodo.23715027

The repository also carries a CITATION.cff file, which GitHub uses for its "Cite this repository" button.

What licence is it under?

GPL-3.0-or-later. Versions before August 2026 were released under the MIT Licence; as sole copyright holder, David M. Berry relicensed all past and present versions under GPL-3.0-or-later. The full text is in LICENSE.

03 · Setup

Keys and models.

Which API keys do I need?

Only a Zotero key, to read your library. Every model runs locally. See the Zotero API key walkthrough, and the Vector Lab FAQ for questions that apply across all the instruments.

Which models should I choose?

See Choosing models on the Operations page. The model pickers in the app also mark the recommended starting point.
